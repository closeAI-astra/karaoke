# ピッチ採点ステージ

歌の音声・動画を読み込むと、音程をカラオケのように流して表示し、最後に点数をつけるアプリです。
GitHub Pages で公開すると、このリポジトリの `media/` フォルダに置いた音声・動画が「曲ライブラリ」に自動で並びます。

ファイルの解析はすべて見ている人のブラウザの中で行われ、どこにも送信されません。

## 画面の見かた（通信カラオケの採点画面風）

- **音程バー（画面の上の帯）**：1区間ぶんのガイドバーが並び、縦線とハート（今の自分の声の高さ）が左から右へ進みます。右端まで行くと次の区間に切り替わり、右上の「演奏区間」の番号が進みます。通過したバーは、音程が合っていれば金色、外れると灰色になります。
- **テクニック表示**：しゃくり・こぶし・フォール・ビブラート・アクセント・ロングトーンを検出すると、その場所にアイコンが出て、帯の下の回数が増えます。
- **フレーズごとの音程**：1フレーズ歌い終えるたびに、そのフレーズの音程一致率が出ます。
- **歌詞（画面の下）**：2行で表示し、歌った部分から色が変わります。漢字には自動でふりがなが付きます。歌詞がないときは、ガイドの音をドレミで表示します。
- **採点結果**：小数第3位までの総合点、5項目（音程・安定感・抑揚・ロングトーン・テクニック）のレーダーチャート、テクニックの回数、フレーズごとの一致率グラフを表示します。

## フォルダ構成

```
index.html                 アプリ本体（1ファイル）
media/                     ここに曲を置く
  sample-melody.wav        サンプル（合成音声。わざと4か所ずらしてある）
  sample-melody.ref.wav    サンプルのお手本
  sample-melody.lrc        サンプルの歌詞（LRC形式）
  index.json               曲名の表示用（なくても動く）
vendor/kuromoji/           自動ふりがな用の形態素解析器と辞書（kuromoji.js、Apache License 2.0。NOTICE.md に辞書の出典）
.nojekyll                  GitHub Pages にファイルをそのまま配信させるための空ファイル
```

## 公開手順

1. GitHub で **Public** のリポジトリを作る（例：`pitch-stage`）。
2. このフォルダの中身をすべてリポジトリに置く（`git push` するか、ブラウザの「Add file → Upload files」）。
3. リポジトリの **Settings → Pages** を開き、Source を「Deploy from a branch」、ブランチを `main`、フォルダを `/ (root)` にして保存する。
4. 数分後に `https://ユーザー名.github.io/リポジトリ名/` で開けるようになる。

## 伴奏入りの音源について

原曲やカラオケ音源など、伴奏が入った音源でもそのまま使えます。「音源の種類」が「自動で判定」のときは、伴奏が入っているかを判定し、入っていればボーカルだけを抜き出して音程を求めます（左右のチャンネルでまん中に定位している成分を残し、倍音の並びからいちばん強いメロディの線を選び、ピアノやパッドのように揺れのない線は捨てます）。うまくいかないときは「伴奏入り」「ボーカルだけ」を手動で選べます。

## 歌詞を表示する

- **曲と一緒に置く**：`media/` に `曲名.lrc`（または `曲名.txt`）を置くと、同じ名前の曲と自動で組になります。例：`kaeru.mp4` と `kaeru.lrc`
- **画面から読み込む**：「歌詞」の欄で .lrc / .txt ファイルを選ぶか、「貼り付け・編集」に貼って「反映する」を押します。
- **時刻なしでもよい**：行頭に `[00:12.34]` のような時刻を書けば（LRC形式）その時刻に表示します。時刻がなければ、歌声のフレーズに合わせて自動で各行を割り当てます。
- **タップで合わせる**：曲を流しながら、各行の歌い出しで Space キー（またはボタン）を押すと時刻が決まります。「LRCを書き出す」でファイルに保存できるので、`media/` に置けば次回から使えます。
- **ふりがな**：漢字には自動でふりがなが付きます（辞書は `vendor/kuromoji/` にあり、初回だけ約18MBを読み込みます）。自分で付けるときは `{世界|せかい}`・`｜世界《せかい》`・`世界(せかい)` の書き方が使えます。英語に読みを付ける例：`{I will|アイ ウィル}`
- 画面で編集・タップした歌詞は、このブラウザに曲ごとに保存されます。

## 曲を追加する

- `media/` に音声（mp3・m4a・wav・ogg・flac など）か動画（mp4・webm・mov）を置くだけで、次に開いたときに一覧に出ます。
- **お手本と組にする**：`曲名.ref.拡張子` という名前で置くと自動で組になります。
  例：`kaeru.mp4`（自分の歌）と `kaeru.ref.mp3`（お手本）
- **曲名を日本語で表示したい**ときは `media/index.json` に書きます。

```json
[
  { "file": "kaeru.mp4", "title": "かえるの歌（2回目の録音）" },
  { "file": "take3.m4a", "title": "練習テイク3", "ref": "guide.mp3", "lyrics": "kaeru.lrc" }
]
```

`ref` を書けば、名前のルールに関係なくお手本を指定できます。`lyrics` で歌詞ファイルも指定できます。

## ファイルサイズについて

GitHub の公式ドキュメントでは、ブラウザからアップロードできるのは1ファイル25MiBまで、`git push` では100MiBを超えるファイルは拒否されます。
このアプリは Git LFS で管理されたファイルには対応していません。長い動画は音声だけ（m4a や mp3）に書き出して置くのがおすすめです。

## 便利なURL

| URL の付け足し | 意味 |
|---|---|
| `?song=kaeru.mp4` | 開いた瞬間にその曲を読み込む（曲を選ぶと自動でアドレスに付きます。共有用） |
| `?repo=ユーザー名/リポジトリ名` | 別の公開リポジトリの曲一覧を読む |
| `&dir=songs` | `media` 以外のフォルダを読む |
| `&branch=dev` | 既定以外のブランチを読む |

1つのファイルだけ読みたいときは、画面の入力欄に GitHub のファイルURL（`https://github.com/…/blob/main/…` の形でも可）を貼れば読み込めます。

## 注意

- 一覧の取得には GitHub API を使います。ログインなしの利用回数には上限（1時間あたり60回）があり、超えると一時的に一覧が出なくなります。そのときは `media/index.json` に曲を書いておくと、そちらから一覧を作ります。
- 非公開（Private）リポジトリの曲は読めません。
- 動画はアプリと同じリポジトリに置くのが確実です。別リポジトリやURL指定の動画は、ブラウザによっては映像が表示されないことがあります（その場合も音声で採点します）。
- 伴奏入りの音源ではボーカルを抜き出しますが、ボーカルと同じ高さで揺らしながら鳴る楽器や、左右に広げられたボーカルは区別しきれないことがあります。ボーカルだけの録音がいちばん正確です。
